## Authority Boundary

`ROAD_WARRIOR_CURRENT_STATE.md` is the authoritative derived operational snapshot. It does not govern frozen requirements, durable architectural decisions, implementation sequencing, or historical evidence. GitHub remains authoritative for those concerns.

Authority and conflict order is:

1. Current observed reality and verified external state.
2. Approved repository governance for requirements and durable decisions.
3. Repository implementation plans and evidence records for recorded status.
4. `ROAD_WARRIOR_CURRENT_STATE.md` for derived operational orientation.
5. Native Project memory for recognition and history.

A material conflict must be stated and resolved from the appropriate evidence. The snapshot cannot silently amend governance. A newer verified fact may expose stale documentation, but it must be labeled and reconciled rather than silently upgraded into governed truth.

## Update Responsibility and Triggers

Road Warrior judgment decides whether a material event changes current state. A surface with verified Drive write capability updates the same file ID and verifies it by independent readback. Bruce approves governed changes when required but is not the manual synchronizer.

Update only for:

- A material phase, convergence-mode, or hard-date change.
- A capability proven, disproven, degraded, or materially bounded.
- An approved major decision that changes current operation.
- A trip-readiness priority added, completed, removed, or reordered.
- A meaningful change in where Road Warrior should resume.
- Correction of a materially inaccurate snapshot claim.

## Anti-Bloat Rules

- Keep the snapshot to approximately one rendered page and under roughly 800 words.
- Replace current state; do not append a narrative history.
- Keep at most five ordered priorities and five recent material changes.
- Include only trip-relevant capability boundaries.
- Keep detailed evidence and durable decisions in repository records.
- Update the `State as of` value on every write.
- Remove completed priorities unless their completion materially defines current capability.
- Do not store transcripts, broad project history, or speculative later architecture.

## Project-Instruction Rule

> Before answering about Road Warrior’s current phase, readiness, capabilities, limitations, priorities, or next action, retrieve and read `ROAD_WARRIOR_CURRENT_STATE.md` from the configured Project source; do not answer operational-state questions from native memory alone. If retrieval fails, the source appears stale, or a material conflict exists, state the boundary and resolve it from the appropriate authoritative evidence before making consequential judgments.
